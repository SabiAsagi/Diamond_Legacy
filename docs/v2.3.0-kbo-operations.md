# 2.3.0 — KBO 구단 운영과 Steam 데스크톱 기반

목표는 OOTP의 선수단·라인업·거래·재정·시즌 운영 흐름을 참고한 한국 야구 GM이다. 현재 버전은 핵심 운영을 연결한 첫 단계이며 OOTP 전체 기능을 재현한 완성판은 아니다. 해외 리그·외국인/아시아 쿼터 영입, 자체 뷰어, 시각 디자인 고도화는 다음 단계다.

## 이번 구현

- 10개 프로 구단, 북부·남부 각각 6개 퓨처스 팀. 상무는 북부, 울산 웨일즈는 남부. 프로 10개 구단에 3군 재활 조직을 추가했다.
- 1군 등록과 당일 출장 명단 분리, 타순·선발 로테이션·마무리 저장, 1군 말소 후 10일 재등록 제한. 3군은 공식 경기를 치르지 않고 회복을 우선한다.
- 관전과 자동 진행을 같은 타석 엔진으로 연결했다. 경기 종료, 타순 교대, 끝내기, 볼넷 밀어내기, 안타·득점·투구 이닝을 집계한다. 관전 결과를 두 번 계산하지 않고 팀·선수·시즌 결과를 함께 저장한다. 경기 중 선수 기록은 별도 사본에서 진행하므로 저장 실패 후 재시도할 수 있다.
- 퓨처스는 별도 일정·순위·개인 성적을 사용한다. 1군에 승격해도 2군 성적을 1군 성적에 섞지 않는다. 북부·남부 상위 2팀의 교차 준결승과 단판 결승을 구성했다.
- 육성선수 계약 신분을 별도로 관리한다. 정식 68명 정원에서 제외하고 퓨처스 출전·3군 재활을 허용하며 1군 출전은 차단한다. 5월 1일 이후 정식 전환할 때 정원을 검사한다. 당해 시즌 방출 선수의 육성 계약을 제한하고 고졸 육성 계약은 연 5명까지 제한한다.
- 자유계약 영입, 우리 선수 계약 갱신, 보장 연봉을 남기는 방출, 1~3명 트레이드와 상대 평가, 예산 초과 차단.
- 정규시즌 → 와일드카드 → 준플레이오프 → 플레이오프 → 한국시리즈 → 11라운드 드래프트 → 비시즌 → 다음 시즌. 육성 모드에서 연결한 후보도 직접 지명할 수 있다.
- 월간 성장·노화, 피로·부상과 복귀일, 거래 기록, 역대 팀·선수 시즌 기록, GM 저장 백업 내보내기.
- Steam용 Windows 배포 폴더 생성. 네트워크 없이 로컬 자료로 실행하며 고정된 앱 저장 공간을 쓴다. F11 전체화면과 화면 확대/축소, 저장 폴더 열기 지원.

## 아직 단순화된 부분

- 퓨처스 날짜는 공식 경기 수·리그간 대전 수·휴식 요일에 맞춘 게임 일정이다. 실제 2026년 경기 날짜를 그대로 복제하지 않는다. 1군 기존 일정 데이터는 유지한다.
- 신인 지명은 현재 시즌 종료 후 진행한다. 실제 9월 행사 시점, 계약금, 신인 다음 연도 등록, 지명권 거래·지명 포기는 추가해야 한다.
- 연봉 협상·트레이드 평가는 자체 산식이다. KBO FA 자격·등급·보상선수, 샐러리캡·초과 제재, 연봉 조정, 계약 옵션, 웨이버·육성선수 선발 자격의 세부 예외은 미구현이다. 계약 만료 선수는 자유계약 시장에 등록하지만 이 상태가 실제 FA 자격 취득을 뜻하지 않는다.
- 3군은 게임 내 재활 조직이며 KBO 공식 3군 리그를 뜻하지 않는다. 상무는 독립 퓨처스 선수단으로 구성하며 실제 입대 선발·원 소속 구단 복귀·복무기간은 후속 단계다. 울산 선수의 프로 지명 규정도 후속 단계다.
- 확장 엔트리, 포스트시즌 특별 엔트리, 1·5위 결정전과 동률 상대 전적 규정, 퓨처스 승부치기·더블헤더·우천 재편성, 시범경기·캠프 일정은 후속 구현이다.
- 타석 엔진은 아직 투구별 ABS·피치클락, 실책·희생플라이·사구·병살·수비 위치 적합도, 주자별 투수 책임과 공식 승리/패전/세이브·홀드 요건을 모두 재현하지 않는다. 선수 성적은 게임 집계이며 공식 기록원 수준의 계산을 완료했다고 표현하지 않는다.
- OOTP식 코칭스태프·스카우팅 불확실성·세부 전략·구단주 목표·수입/지출 전체 재정·AI 장기 로스터 구성은 추가 단계다.
- Steamworks 업적·클라우드·오버레이·상점·Depot 업로드·서명은 미설정이다. 이번 빌드는 로컬 실행용 데스크톱 기반이다. 기존 브라우저 저장은 앱 저장 공간에 자동 이관되지 않는다.

## 저장 보존과 예산

기존 선수·육성 커리어 ID와 기록을 유지한다. GM 조직 최초 준비 시 부족한 1·2군 선수를 추가한다. 이전 budget은 잔여 예산이었으므로 기존 연봉 부담을 더해 총 연봉 예산으로 한 번만 전환한다. 기존 연봉 자체는 임의로 변경하지 않는다. 데이터베이스 이름은 기존 DiamondGMDatabase를 보존한다.

## 실행

- `npm run desktop`: 로컬 데스크톱 실행.
- `npm run build:steam`: `release/win-unpacked/Diamond Legacy.exe`와 필요한 파일들을 생성한다. 폴더 전체가 실행 패키지다.
- `npm run build:windows`: 휴대용 Windows 실행 파일 생성.
- `npm test`, `npm run lint`: 기존 육성 검사와 GM 검사를 유지한다.

디자인과 기능을 수정한 뒤 추가된 TSX 화면의 상태·접근성·오류 처리를 React Best Practices 체크리스트로 점검한다.
